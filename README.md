# Прототип ВКР: схемы процессов и макет сервиса

Статический сайт-прототип к ВКР, опубликованный на GitHub Pages. Чистый HTML + CSS + JavaScript,
без сборки, зависимостей, внешних библиотек и серверной части.

Сайт состоит из трёх частей:

* **Схемы процессов** (`flows/`) — как устроены процессы перевода сейчас и что меняется в цифровом
  сервисе; открывается в корневой оболочке по умолчанию;
* **Макет сервиса** (`mockup/`) — минималистичный макет «Центра поддержки и заявок» для студента:
  обращения по переводу, документы, проверки, история;
* **Прежний прототип разделов ТЗ** (`legacy-mockup/`) — большой кликабельный макет по концептуальному
  ТЗ (заявки, тикеты, панели администратора, редактор вида). Сохранён как есть.

## Как открыть

Double-click по `index.html` в корне (Chrome / Edge / Яндекс.Браузер). Сервер не нужен.

В верхней панели два переключателя — «Схемы процессов» и «Макет сервиса»; выбор запоминается в
`localStorage` (ключ `shell-mode`). Справа в панели — ссылка «прежний прототип разделов ТЗ», она
открывает `legacy-mockup/index.html` в новой вкладке.

Обе панели работают и при открытии с диска (`file://`), и на Pages. Если браузер блокирует
`localStorage` (например, приватный режим), переключатель просто не запомнит последний режим —
сами страницы продолжат работать.

## Публикация на GitHub Pages

Сайт полностью статический, публикуется как есть, без сборки: репозиторий отдаётся целиком
из корня ветки `main`. Файл `.nojekyll` отключает обработку Jekyll, чтобы папки отдавались как есть.

Адрес страницы: <https://kaelth4s.github.io/ikbfu-thesis-site/>

Настройка (один раз): **Settings → Pages → Source: Deploy from a branch → Branch: `main`,
папка `/ (root)` → Save**. Дальше изменения подхватываются автоматически после `git push`.

## Что где менять

| Что | Файл |
|---|---|
| Услуги, обращения, сроки, документы, проверки, уведомления макета | `mockup/mockup-data.js` |
| Тексты, статусы и этапы схем процессов | `flows/flows-data.js` |
| Оформление макета: акцентный цвет, отступы, сетка, адаптив, печать | `mockup/mockup.css` (токены в `:root`) |
| Список режимов оболочки, подпись и ссылка в панели | `index.html` |
| Прежний прототип разделов ТЗ | `legacy-mockup/` (менять не нужно) |

Данные собраны в отдельные файлы, поэтому правка сроков, документов или названий не требует
трогать разметку: `mockup.js` только отрисовывает то, что лежит в `mockup-data.js`.

## Макет сервиса — демонстрационный

`mockup/` показывает пользовательский путь по четырём услугам перевода:

* «Мои обращения» — список обращений со статусом, сроком и строкой «что дальше»;
* карточка обращения — этапы, документы (чипы «получено из ИС», «автопроверка», «нужно приложить»,
  «донести оригинал»), проверки, история;
* «Каталог услуг» — те же четыре услуги с чек-листом документов и сроками;
* «Уведомления» — события, привязанные к обращениям.

Границы демонстрации:

* кнопки «Подать заявление», «Донести оригинал», «Скачать выписку» только меняют состояние
  интерфейса и пишут событие в историю — запросов к серверу нет, файлы не формируются;
* состояние демо хранится в `localStorage` браузера (ключ `mockup-state`), кнопка **«Сбросить демо»**
  возвращает исходное состояние;
* персональных данных нет: ни ФИО, ни телефонов, ни номеров приказов; время событий относительное
  («сегодня, 10:20», «12 минут назад»);
* макет адаптируется до 900 px и корректно печатается (`@media print`).

## Прежний прототип

`legacy-mockup/` — кликабельный макет по концептуальному ТЗ (роли, заявки, тикет-система, панели
администратора, конструктор заявок, редактор внешнего вида). Он сохранён без изменений, включая
собственный редактор вида и сохранение настроек в `localStorage`. Ссылка на него — в верхней панели
корневого `index.html`.
